## Q1. Euronext Oslo Børs NewsWeb: API/RSS/push, categories and IDs, attachments, issuer IDs, timestamps, history depth, and what changed under Euronext (2024–2026)

### Takeaway
NewsWeb is still live in October 2026 (message IDs are around 677,000–683,000). It has **no documented public API, RSS or push channel**. Its JavaScript single-page app is backed by an **undocumented, keyless JSON API at `https://api3.oslo.oslobors.no/v1/newsreader`** (`/list`, `/message`, `/attachment`, `/categories`, `/markets`, `/issuers`, ...). Many 2026 open-source projects poll that API, and it exposes a stable numeric category taxonomy (1001–1302) that already encodes most trading-relevant Norwegian event types (inside information, PDMR trades, flagging, buybacks, reports, ex-dates, trading halts). It is the single most valuable free Norwegian source for both sleeves [ST][LT]. However, it is unofficial: there are no published ToS/SLA, it "may stop working without warning", and the request-cap behaviour is reported inconsistently.

### Inferences
- **Catalog entry, NewsWeb reader API.** Owner: Euronext Oslo Børs. Access: undocumented JSON over HTTPS (GET or POST), no auth. Endpoints: `/v1/newsreader/list?fromDate&toDate[&issuer][&category][&market][&messageTitle]`, `/message?messageId`, `/attachment?messageId&attachmentId`, `/categories`, `/markets`, `/issuers`. Key fields: as listed above. History: at least 2017. Latency: publication is immediate; the user's delay equals the polling interval. Cost: free. ToS: none published that I could find; treat as unofficial and fragile. Sleeves: [ST] for 1005/1202/1006/1102/1007/1104/1103; [LT] for 1001–1003, 1101, 1007/1008/1009.
- **Polling design for the short-term sleeve.** Because the API is day-granular and has no push, poll `/list?fromDate=<today>&toDate=<today>` (Oslo calendar date) about every 30–60 s in a 06:30–18:30 CET window, and every 5–10 min otherwise. That is about 1–2k light calls per day, comparable to the pacing in existing clients. Diff on `messageId`, then fetch `/message` (and attachments only for reports, prospectuses and inside information) for new IDs. Always check `overflow` and bisect if it is set, since the true cap (50 vs 601) is unresolved.
- **Ticker mapping.** `issuerSign` appears to be the Oslo ticker (e.g. EQNR, NOD). Map it to Nordnet instruments via ticker+market, and use ISINs from another reference source if `/issuers` lacks them (unknown).
- **The category alone does not give direction.** 1005 "inside information" covers profit warnings, contract wins, M&A and private placements alike, so it needs text classification and sentiment (see Q6). 1104 non-regulatory press releases often carry order/contract news that is useful for [ST].
- **Corrections.** Use `correctionForMessageId`/`correctedByMessageId` to supersede earlier records, avoiding double-counting and stale numbers.
- The Euronext changes in 2024–2026 that matter for a data consumer are institutional (rebrand, Finanstilsynet supervision from 1 Apr 2025) and on the live.euronext.com website (anti-bot). The NewsWeb reader API was evidently unchanged and in heavy open-source use through at least Sep 2026.
- The Optiq cash-market cutover date implied by "17 months after Oslo Børs joined Euronext" plus "9 November" is November 2020, assuming Euronext's June 2019 acquisition. The year itself is not stated in the snippets I saw.

### Gaps
- Official ToS/licence for automated access to newsweb.oslobors.no / api3.oslo.oslobors.no: not found (euronext.com blocked, search budget exhausted). Euronext presumably licenses Oslo news commercially via its data products, but the content and price of "Oslo Børs Products" could not be read.
- The true per-call cap (50 vs 601), whether it depends on filters, and whether `issuer` accepts both ticker and numeric ID: conflicting sources, not tested live.
- Publication→API latency (seconds?) and any CDN caching: not measured. Live verification was denied by the permission system.
- Whether NewsWeb will be replaced by a Euronext-wide service (e.g. live.euronext.com company news): no evidence either way.
- The name and ID of a "Finansiell kalender" category, if it is distinct from the 1001–1302 list. The bjelle-ai map does not include one, so it may fall under 1010/1104 (unknown).
- Whether `/issuers` returns ISINs: unknown.

## Q2. Sweden: Nasdaq Nordic company announcements, MFN, Cision, GlobeNewswire, Spotlight and NGM (coverage, free machine-readable feeds, latency, publication times)

### Takeaway
Sweden has no single official free feed. Regulated releases go out through competing commercial wires (mainly MFN, Cision and GlobeNewswire) and are aggregated by Nasdaq's company-news service (CNS) and by MFN's public site.

The most practical free machine-readable options are:
- **MFN's site JSON** (`https://mfn.se/all/a.json?limit=…`). It aggregates all Nordic listed companies "regardless of provider", with ISIN/tickers, machine-readable tags (`:regulatory`, `sub:report:interim`, `sub:ci:insider` …) and full text inline. However, **mfn.se/robots.txt disallows `*.json`, `*.rss`, `*.xml` and `*.atom`**.
- **Nasdaq CNS** `query.action` JSON and RSS. However, one 2026 project notes that **Nasdaq's website terms forbid automated capture**.
- **Per-issuer Cision RSS / Cision PAPI JSON**, with a documented ≤2-minute delay.
- **GlobeNewswire country RSS.**

For lowest latency, MFN offers **WebSub push** per issuer, but that needs a public HTTPS callback. I found no machine-readable feed information for Spotlight or NGM (not researched; WebSearch budget exhausted).

- **Catalog: MFN all-feed** `https://mfn.se/all/a.json?limit≤200&offset`. No auth, free. The robots.txt disallow is a clear "no automated access" signal, so a personal app should poll only at low frequency or ask MFN for permission/licensing (Dataflow). The coordinator says mfn.se is reachable via curl, but live verification was denied here.
- **Catalog: MFN per-issuer** `feed.mfn.se/v1/feed/{entity_id}(.json)` and the WebSub hub. This is the intended public consumption path for issuer websites (MFN publishes client libraries and a WordPress plugin for it), so it is lower legal risk for a watchlist. Latency is near-real-time with WebSub, but a personal app without a public endpoint must poll.
- **Catalog: Nasdaq CNS** `query.action` and RSS. Free and no auth, covering all Nasdaq Nordic issuers (Stockholm, Copenhagen, Helsinki, Iceland, First North) with uniform category strings. - **Catalog: Cision.** Per-issuer RSS and PAPI JSON give official, documented, keyless feeds with ≤2 min latency and an `IsRegulatory`-style filter. They suit a watchlist, but you must collect feed IDs per issuer.
- **Catalog: GlobeNewswire.** Country RSS is a cheap catch-all for releases distributed via GlobeNewswire, including some Norwegian issuers.
- **Coverage logic.** A Swedish issuer appears on (a) its own wire (MFN, Cision or GlobeNewswire), (b) Nasdaq CNS if listed on Nasdaq Stockholm/First North, and (c) mfn.se's aggregate stream. For complete Swedish coverage, (b) or (c) suffices. For speed on a watchlist, (a) is best.

## Q5. Financial calendars (earnings dates, AGMs, ex-dividend/record dates, capital-markets days) for NO/SE in machine-readable form

### Takeaway
There is no free, official, consolidated machine-readable Nordic corporate calendar.

Practical options:
- **Börsdata API** (Sweden-based, covers Nordic companies) has `report/calendar` and `dividend/calendar` endpoints. It is paid: the REST API now requires the PRO+ tier (reported 599 kr/month) for new members since 1 Feb 2025.
- **Primary announcements:**
  - NewsWeb "Finansiell kalender" messages and category 1101 ex-date.
  - Nasdaq CNS categories "Financial Calendar", "Notice to general meeting" and "Decisions of general meeting".
  - MFN tags `sub:ci:gm:notice`/`sub:ci:gm:info`.

- **Issuer IR calendar widgets** (MFN/Cision).
- **Euronext Oslo Børs Financial Calendar** (a commercial data product; details blocked).

Calendars are mostly [LT] (scheduling and dividend features), but known report dates are also crucial [ST] context, e.g. avoiding or targeting pre-earnings windows and flagging surprise announcements.

## Q6. Processing: classifying and scoring Nordic-language financial news (LLMs, NorBERT/NB-BERT/KB-BERT, FinBERT on translated text), deduplication, and a trading-oriented event taxonomy mapped to sleeves

### Takeaway
The best practical pipeline for a personal app has three stages:
1. **Exploit the free structured labels already in the feeds**: NewsWeb category IDs, Nasdaq CNS category strings, MFN `sub:`/`:regulatory` tags, Cision regulatory flag/InformationType.
2. Use **rules** for deterministic categories (buybacks, PDMR, reports, calendars).
3. Send only ambiguous items ("Inside information", "Company Announcement", Oslo 1005/1104) to an **LLM for structured extraction** of event type, direction, magnitude and numbers. Open-source Nordic projects already use exactly this split.

For local models:
- **NB-BERT** (Norwegian, also retains Swedish/Danish) and **KB-BERT** (Swedish) are the strongest open encoders. NB-BERT-base scores 84.04 F1 vs 73.27 for mBERT on Norwegian sentiment.
- Domain sentiment needs labelled financial data: a ~15k-example Swedish fine-tune reached only ~60% accuracy.
- English FinBERT is best applied to the **English versions many Nordic issuers publish in parallel** (linked via MFN `group_id`), not to machine translations.

Deduplicate with the native IDs (NewsWeb `messageId` and correction links, MFN `group_id`, Cision `EncryptedId`) plus a cross-feed key (ISIN/ticker + normalised title + time window).

### Inferences
- **Recommended processing pipeline.**
  1. Ingest per-source records with native IDs.
  2. Normalise to `(source, native_id, issuer_isin/ticker, published_utc, lang, title, body, native_category/tags, is_regulatory, attachments)`.
  3. Cluster duplicates. Use the exact native links first (MFN `group_id`, NewsWeb corrections). Then use a cross-feed key: same issuer, |Δt| ≤ 10 min, and title similarity (e5 cosine ≥ ~0.9 or normalised-title match), so that NewsWeb + GlobeNewswire + NTB copies, or MFN + Nasdaq CNS copies, collapse into one *event*. Keep the earliest timestamp as the event time and log per-source lags.
  4. Map native categories with rules.
  5. Send ambiguous items to an LLM, prompted in the source language. Modern multilingual LLMs read Norwegian/Swedish directly, so no translation step is needed; check EuroEval leaderboards when choosing a model. The LLM returns JSON: `event_type` (taxonomy below), `direction` (−1/0/+1), `surprise_magnitude` (0–3), `numbers` (e.g. order value, placement size and discount, guidance range, dividend per share), `is_price_sensitive`, `horizon_hint`.
  6. Optionally add a fine-tuned NB-BERT/KB-BERT sentiment head, trained on the app's own logged outcomes (abnormal return labels), as a cheap second opinion.
  7. Log predictions vs outcomes (as the app already plans) so that the per-event-type weights are learned.
